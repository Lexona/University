6) contenuto di un rda scope statico e dinamico.
Risposta:
Analogamente a quanto avviene per un blocco d’istruzioni, di cui una procedura è astrazione, il record di attivazione
rappresenta l’intero ambiente di esecuzione di una procedura. La forma generale di un record di attivazione consiste di tre parti:
1. L’ambiente locale: tutti i data object che sono definiti all’interno della procedura;
2. L’ambiente non locale: tutti i data object la cui definizione è propagata da altre procedure;
3. L’ambiente dei parametri: contiene informazioni sui dati che sono passati dalla e alla procedura.
Ogni volta che una procedura viene invocata il suo record di attivazione viene aggiunto al cosiddetto stack di attivazione
Esempio slide 27 Bonatti, perché le variabili nell'rda possono subire modifiche diverse in base alle procedure richiamate e l'ambito in cui sono richiamate.

7) Perche in un linguaggio perfetto (sia staticamente che fortemente tipizzato e Turing completo) non può esistere garbage collector
Risposta:
Se esistesse dovrebbe liberare automaticamente la memoria non più utilizzata, rendendola più efficiente e rendendo anche più efficiente la programmazione,
se una funzione dovesse avere delle variabili in disuso allora verrebbero rilasciate, questo significa che, in un esempio di Linguaggio Perfetto, il codice:
int x;
P;
x="pippo";
Con P un generico programma dovrebbe rendere non solo P decidibile (perché P dovrebbe terminare prima o poi per arrivare a x="pippo"), ma in più il garbage collector
dovrebbe verificare quali sono le variabili che non sono più utili al programma, quindi si andrebbe in conflitto con l'ipotesi per  cui il Linguaggio Perfetto è
Turing Completo.

8) classi interne polimorfismo fammi la quadrupla(?) di questo codice java e in c(spiegando le differenze)
Tipi di polimorfismo: ad-hoc, universale, parametrico e inclusione. 
In C non c'è un modo intrinseco di avere il polimorfismo, anche perché non è un linguaggio del paradigma orientato agli oggetti, invece Java supporta il polimorfismo
ad hoc (binding statico), un esempio semplice è l'addizione con + che effettua l'overloading o la coercizione di tipo per le stringhe (ad esempio nella stampa, o 
nell'addizione di  un int con un reale), universale (binding dinamico) con 2 classi (con metodi che hanno lo stesso nome) A e B, B estende A, se dichiaro una variabile 
x, di tipo A, ma prima scrivo x = new A(), x.metodo() e poi x = new B(), x.metodo(), nel primo caso accederà al metodo() in A, nel secondo caso accederà al metodo() 
in B, parametrico è dato da metodi o classi che accettano un tipo generico e lo sostituiscono appena viene dichiarato un nuovo metodo, del tipo, nella classe A 
precedentemente menzionata avrà un metodo public <T> swap(T x, T y) che effettui lo scambio tra x e y, facendo in modo che x e y possono essere di qualsiasi tipo,
come delle stringhe, degli int, dei float e così via.

15) fai un esempio di signature e structure
Risposta:
Le signature sono usate per costruire interfacce, le structure si usano per costruire classi.

 signature STACK =
 sig
 type 'a stack
 (∗ dichiara un tipo parametrico 'a stack senza definire come è definito ∗)
 val empty : 'a stack (∗ una funzione per costruire uno stack vuoto ∗)
 val push : ('a ∗ 'a stack) ->- 'a stack
 val pop : 'a stack ->- ('a ∗ 'a stack)
 end;

structure Stack :> STACK =
 struct
 type 'a stack = 'a list;
 val empty = [];
 fun push (x,s) = x ::: s;
 fun pop (x:::s) = (x,s);

E si nota come con :> si sta implementando l'interfaccia STACK in Stack (in questo caso lo stack è una lista)

35) Cosa sono le Macchine astratte?
Risposta:
Dato un linguaggio di programmazione L, una macchina astratta per L (in simboli ML) è un qualsiasi insieme di strutture dati e algoritmi che permettono di 
memorizzare ed eseguire i programmi scritti in L.
2 concetti fondamentali sono la memoria, per immagazzinare informazioni e il processore, che esegue le istruzioni scritte nel linguaggio L.

type non crea costruttori di dati, mentre datatype sì.
